# 实时视频、深度和雷达点云检查网页

这个工具在 Mac 浏览器中显示 G1 的彩色画面、D435i 深度图和 MID360 雷达点云，面向本次测试设备；连接其他机器人前需重新核对配置和适用条件。机载服务只监听本机地址，Mac 通过 SSH 转发访问；图像、点云和登录密码不上传外部服务。

## 连接与启动

1. 将 Mac 网线接到目标机器人的开发网口，确认能 SSH 到机载计算单元；本次地址为 `192.168.123.164`。网卡设置见 [简明使用指南](usage.md#1-连接设备)。
2. 确认头部摄像头的 USB-Type-C 已接到机载电脑。只有网线、相机 USB 未连接时，网页会显示相机未发现。
3. 在本项目目录运行：

```sh
python3 scripts/start_sensor_web.py --host 192.168.123.164 --name g1-01
```

首次连接需要在终端核对 SSH 指纹并输入该机器人的 SSH 密码。启动成功后会自动打开 [实时检查页面](http://127.0.0.1:8765)。点击 **连接预览**，即可看到彩色视频、深度伪彩图和雷达点云；相机型号、USB 序列号、USB 连接速度、当前采集速率和数据更新时间同时显示。保留启动终端。

彩色通道读取厂家的头部视频 RPC，不直接抢占 RGB 设备节点。若 `video_hub_pc4` 原本停止，先核对厂家配置中的视频节点确属 D435i RGB 接口，再临时开启；停止预览时恢复并确认。原本运行的头部视频服务保持运行，胸部视频服务不变。深度通道识别 Intel D435i 的 USB 身份，再只读探测 Z16 节点；找不到设备、发现多个候选或节点被占用时明确报错，不随便选择另一相机。界面显示的序列号来自 USB 身份，RGB RPC 图像本身不携带序列号，不把两者包装为独立认证的绑定关系。

雷达使用官方 `rt/utlidar/cloud_livox_mid360` 话题。如果原有 `lidar_driver` 已停止，连接预览时会临时开启它；停止时恢复并查询确认。原来已经开启则保持开启，不启动 SLAM 或运动服务。雷达驱动本身可能按其配置初始化通信参数，本工具恢复的是服务启停状态，不承诺驱动内部参数字节不变。雷达默认 IP 为 `192.168.123.120`，不同配置可传入 `--lidar-ip`。型号来自当前只读查询的 `product_info`，未确认时显示「型号未确认」，不按机器人生产日期推断。已识别 MID360s 的型号字符串，但其点云实机兼容性尚未验证。

## 查看与保存

- 两路预览最多约 10 帧/秒；显示的是本程序收到的图像速率，不是传感器的额定帧率。
- 深度图采用固定原始值范围 300–5000，近端蓝色、远端红色，0 和 65535 显示为黑色。原始值没有经过本工具的距离标定，不能直接读作米或毫米。
- 画面陈旧、读取失败或网络断开会显示遮罩与错误。停止后清除旧图；不能把冻结的旧帧当成实时画面。
- **保存当前帧** 只接受当前会话的新鲜画面，过期图像会拒绝下载。深度保存的是伪彩图，原始 16 位深度短测另用 [专项工具](../reports/sensors-2026-09-20.md#工具与复现)。
- **下载检查摘要** 保存当前状态 JSON，包含采样时间。摘要不是自动验收证书。
- 点云可拖动旋转、滚轮缩放、复位视角；网页最多每秒取 5 次显示数据，每帧最多显示 6000 个有效非零采样点。界面分别显示原始点数和显示点数，采集帧率来自 DDS 接收统计。保存点云 JSON 仅包含当前预览采样，不是完整原始点云录像。
- 点云接收成功不等于光学测距合格。页面会显示当前 HMS 查询结果；窗口脏污等警告应单独处理，查询失败也不能视为无告警。
- 三路数据没有做时间同步、RGB/深度对齐或内外参标定。深度伪彩图来自 D435i，点云来自 MID360，是不同传感器。本网页不发送运动指令、不启停导航服务。

## 停止与换另一台

点击 **停止** 会停止本工具的三路采集、释放深度节点、恢复本工具开启的头部视频服务和雷达驱动，并清空网页旧图；原本运行的厂家服务保持运行。恢复状态需要数秒，失败会显示错误。再次点击连接可创建新的会话。所有正在预览的页面都关闭后，约 30 秒没有心跳会自动停止采集；每次会话最多 15 分钟，到期后需重新点击连接。多个页面共享同一采集会话，任意页面停止会停止所有页面的本次采集。

完整退出时，在启动终端按 `Ctrl+C`，启动器会请求远程服务退出，关闭自己创建的 SSH 转发和连接。远程文件仅在随机 `/tmp/g1-sensor-web-*` 目录中，无开机启动项；临时目录随系统清理。网络已经中断时无法确认远程清理，应以租约到期和现场状态为准。

连接另一台时，先结束上一台的启动器、换网线，再使用不同的设备名称：

```sh
python3 scripts/start_sensor_web.py --host 192.168.123.164 --name g1-02
```

两台机器人可以使用相同 IP。`--name` 为各台建立独立的 SSH 指纹记录，保存在本项目忽略 Git 的 `.sensor-web/known_hosts`。再次使用同一个名称时，如果 SSH 提示密钥变化，应先核对实际机器人身份；程序不会删除旧指纹或跳过验证。接上后再核对网页显示的相机序列号。

本机端口被占用时，可用 `--port 8766` 并访问打印出来的新地址；机上端口占用则同时指定其他 `--remote-port`。启动器会核对本次服务的实例 ID，避免误打开已有的旧服务。

```sh
python3 scripts/start_sensor_web.py --host 192.168.123.164 --name g1-02 \
  --port 8766 --remote-port 8766
```

## 环境与检查

Mac 端使用现有 Python 3、SSH 和 SCP。机器人需已有 Python 3.8+、`unitree_sdk2py`、Cyclone DDS、NumPy、OpenCV、GCC 和 Linux V4L2 头文件；本次 01、02 均具备。启动器验证实际采集所需的 SDK 子模块，固定已验证的 Python 解释器和 SDK 搜索路径，兼容 SDK 只放在登录目录、尚未安装为系统包的设备。启动器检查依赖后临时上传网页、Python 服务、解析工具和 C 源文件，在机上编译深度工具，不安装额外软件或改变系统配置。

支持参数还包括 `--user`、`--depth-device /dev/videoN`、`--interface eth0`、`--no-open`。即使指定深度节点，也仍核对其 USB 身份和 Z16 能力。调试时可用 `--ssh-control-path` 复用已经认证的 SSH 会话；程序会校验实际远程 IP 和用户，退出时只取消自己的转发，不关闭外部会话。此选项不能与 `--name` 混用。

代码验证：

```sh
python3 -m unittest discover -s tests -v
```

测试不连接机器人。依赖 NumPy/OpenCV 的数据解析和颜色测试在缺少相关库时会明确跳过。浏览器端没有外部 CDN 或构建依赖。

## 2026-09-20 实机验证

在当前 `.164` 上同时验证了 D435i（序列号 `253843060484`）与 MID360（序列号 `47MCN8R0037833`）：彩色为 1920×1080、深度为 640×480，三路接收均约 10 帧/秒。网页取得 30 个不同的点云预览帧，每帧显示 6000 个采样点；浏览器已检查实际图像解码、三维点云、旋转/复位和文件导出。当前雷达持续报告光学窗口脏污 `0x01040002`，界面保留该告警。

启动、停止、重复连接及过期数据拒取已经实机检查。雷达驱动实际关闭状态约在请求后 6.95 秒得到确认，因此恢复等待设为最多 20 秒，浏览器停止请求目前允许 45 秒（含头部视频服务恢复）。停止成功须收到原状态已恢复的证据，不能仅看命令应答。启动初期可能收到全零点云，网页会显示「等待有效点」，不会沿用之前的点云。

独立端口的无心跳测试确认自动停止并恢复原驱动状态，整个过程约 39 秒（含 30 秒租约）；运行中按 `Ctrl+C` 完整退出也返回成功。多个页面共享会话时，仍在预览的页面会继续续租，因此关闭单个页面不一定触发自动停止。

本地共 120 项测试：119 通过，1 项颜色测试因本机缺 OpenCV 跳过；相关后台与雷达的 44 项模拟测试在机器人现有 Python 3.8/OpenCV 环境全部通过，包含该颜色测试。证据位于忽略 Git 的 `evidence/2026-09-20/sensor-web/`。02 的新增适配及实测见下节；每次换机仍应重新核对序列号和当前诊断。项目没有既有版本/更新日志体系，本次不新增版本号。


## 02 设备兼容与排错

2026-09-20 在 02 实际读到的相机仍为 D435i（USB `8086:0b3a`、序列号 `252943061860`），雷达仍为 MID360（序列号 `47MCN7N0033961`、固件 `13.18.2.40`）。厂家产品字符串中的 `BuildTime:2024/12/17` 是固件信息，不能证明机器人生产日期；本工具未核实所述 2026-04 生产日期。

此次修复三个设备差异：

- USB 重新枚举期间，`/sys/.../serial` 短暂不存在。程序现在有限重试，失败时明确提示检查供电、USB 3 数据线及重新连接预览；仍要求唯一、可识别的 D435i Z16 节点。02 稳定后实际为 USB 3、5000 Mbps、总线路径 `2-2.2`，无需更换相机驱动。
- SDK 仅能从 `/home/unitree` 导入，旧预检通过而临时脚本启动后无法导入。启动器现在将验证所得 SDK 路径传给服务进程，不安装或移动 SDK。
- 头部 `video_hub_pc4` 原本关闭，胸部服务运行。网页现在支持上述临时开启与恢复流程；不将胸部视频假作头部彩色画面。

实机已同时取得 1920×1080 彩色、640×480 深度和 `livox_frame` 点云，接收约 10 Hz，每帧点云约 20064 原始点、6000 网页采样点。当前 HMS `0x01040002` 仍表示光学窗口脏污警告，收到点云不代表测距精度验收通过。详情见 [02 实测记录](../reports/sensors-g1-02-2026-09-20.md)。
